# Практика №3. Вариант 1

**Акишев Ақжан Бақытжанұлы.** Отделы `buh`, `sales`, `hr`, по 5 CSV-файлов,
по 200 строк. Храним 5 последних полных резервных копий.

## Что за файлы

- `make_test_data.py` — создаёт 15 учебных файлов, существующие не перезаписывает.
  Генератор использует фиксированное зерно `1`, чтобы повторный опыт с нуля
  давал те же данные. Это не реальные сведения о компании.
- `backup.py` — полный `tar.gz`, JSON-манифест с SHA-256 архива и каждого файла,
  ротация, проверочная распаковка, подробные `missing/extra/changed`, восстановление.
- `test_backup.py` — 10 дополнительных автотестов, используют только временные папки.
- `rpo_rto.md` — расчёт для интернет-магазина из варианта 1.
- `../run_demo.py` — воспроизводит все практические опыты одной командой.
- `../evidence/` — журналы, JSON с измерениями, исходный/искажённый манифесты,
  листинги изменённых функций и скриншоты настоящего терминала.

## Обычный запуск по шагам

В терминале из папки `practice1` (на Linux команда может называться `python3`):

```bash
python --version
python make_test_data.py
python backup.py
```

Нужен Python **3.12 или новее**. Зависимости устанавливать не надо — используются
только стандартные модули Python. Пути привязаны к папке скриптов, а не к случайной
текущей папке терминала.

Запустите `python backup.py` ещё 7 раз, выдерживая пару секунд между запусками.
Генератор данных повторно не запускайте: для сравнения хешей источник не меняется.
После 8 запусков остаются 5 архивов и 5 JSON. В имени есть микросекунды, поэтому
быстрые запуски тоже не перезаписывают предыдущую копию.

Для проверки или восстановления выберите конкретный архив в `backups/`:

```bash
python backup.py verify backups/backup_ДАТА_ВРЕМЯ.tar.gz
python backup.py restore backups/backup_ДАТА_ВРЕМЯ.tar.gz
```

`backup_ДАТА_ВРЕМЯ.tar.gz` — шаблон: **замените его настоящим именем файла**.
`verify` не меняет `company_data`, а `restore` заменяет её выбранной копией.
Перед `restore` убедитесь, что здесь только учебные данные: изменения, сделанные
после выбранной копии, при восстановлении будут потеряны.

## Пример настоящего вывода

Реальный запуск: Python 3.12.14, Linux, 28.10.2026. Последняя из восьми копий:

```text
[OK] Создан backup_20261028_083702_761222.tar.gz: 15 файлов, 12336 байт
  missing / Отсутствуют (0): нет
  extra / Лишние (0): нет
  changed / Изменены (0): нет
[OK] Восстановление проверено: 15 файлов совпадают
[ROTATE] Удалены backup_20261028_083652_334890.tar.gz и его JSON
```

Суммарный размер исходных файлов — **45 737 байт**, последнего архива —
**12 336 байт**. Сжатие: `45737 / 12336 = 3.7076` раза; экономия 73.03%.
JSON не включён в размер архива; это сравнение именно данных с `tar.gz`, а не
всего дискового хранилища резервных копий.

После замены одного символа хеша и удаления записи о другом файле:

```text
  missing / Отсутствуют (0): нет
  extra / Лишние (1): buh/report_2.csv
  changed / Изменены (1): buh/report_1.csv
[FAIL] Восстановленные файлы не совпадают с манифестом
```

`extra` здесь не означает, что в архиве внезапно появился файл: из JSON удалили
его запись, поэтому он стал лишним относительно испорченного списка.
После опыта правильный JSON возвращён. Повреждён отдельный дубликат архива,
поэтому для следующего задания осталась рабочая копия.

После удаления учебной бухгалтерии и восстановления:

```text
[INCIDENT] Удалена company_data/buh; осталось файлов: 10
[OK] company_data восстановлена: 15 файлов; 0.009869 с
[OK] buh вернулась: 5 файлов. Всего 15 файлов; SHA-256 каждого совпал с JSON.
```

Измерение `time.perf_counter()` включает проверку SHA-256 архива, распаковку,
проверку файлов и замену папки. Это время для 45 КБ тестовых файлов, **не** время
восстановления 300 ГБ интернет-магазина. Расчёт для магазина — в `rpo_rto.md`.

## Как это устроено и почему немного отличается от заготовки

1. `make_manifest()` получает относительные имена файлов и их SHA-256.
2. `create_backup()` упаковывает весь источник. Хеши до и после упаковки
   сравниваются: обнаруженное изменение отменяет копию.
3. `verify_restore()` сначала проверяет SHA-256 архива, распаковывает его в
   отдельную временную папку внутри `restore_test/` и сравнивает файлы с JSON.
4. `compare_manifests()` вычисляет разности множеств имён и сравнивает хеши:
   `missing` — только в JSON; `extra` — только после распаковки; `changed` —
   одинаковое имя, но разные хеши.
5. `rotate()` вызывается **после успешной проверки новой копии**, оставляет 5 пар.
6. `restore()` сначала распаковывает и проверяет архив отдельно, затем заменяет
   `company_data`. Старая папка временно переименовывается; если перемещение новой
   папки не удалось, выполняется откат. Удалять повреждённый источник до проверки
   копии, как в упрощённой заготовке, рискованно.

Распаковка использует `tar.extractall(..., filter="data")`; дополнительно запрещены
пути вне `company_data`, `..`, ссылки и специальные файлы. Тесты показывают, что
битый архив или неверный JSON не приводят к замене источника.

## Ограничения учебной программы

- Это полные файловые копии, не инкрементные и не резервирование работающей БД.
  На время копирования файлы должны быть стабильны. Для БД нужен согласованный
  дамп/снимок и/или резервирование журналов транзакций.
- SHA-256 обнаруживает изменение, но JSON не подписан: злоумышленник с доступом
  к архиву **и** манифесту может изменить оба. Права доступа, шифрование,
  неизменяемое/offline-хранение и удалённая площадка здесь не реализованы.
- `company_data/` и `backups/` лежат рядом **только для упражнения**. Это не 3-2-1
  и не защита от потери общего диска или шифровальщика.
- Интервал 2 секунды демонстрирует ротацию, а не производственное расписание.
  Планировщик ежедневных/часовых копий в этой практике не устанавливается.
- Программа не рассчитана на одновременный запуск нескольких процессов backup
  или restore, сбой питания во время замены каталога и полноценную аварийную
  оркестрацию. Для учебной задачи это отдельные производственные улучшения.

## Тесты

Из корня проекта:

```bash
python -m unittest discover -s practice1 -p "test_*.py" -v
```

Проверяются хорошая копия и восстановление; 8 запусков и ротация 5 пар; стабильные
хеши; changed/extra/missing; повреждённый архив и сохранность источника при отказе;
отсутствующий JSON; попытка выхода за папку при распаковке; символическая ссылка;
недопустимый `KEEP_LAST`; быстрые последовательные запуски.
